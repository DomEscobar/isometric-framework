# Glimmerhain: landscape workflow lessons

Historical maintenance note, 2026-10-01. The reusable consumer instructions are in
[landscape iteration](../../skills/isometric-visual-loop/references/landscape-iteration.md).
This case record is not packaged, a production requirement, a starter art library,
or a claim that the full game was accepted.

## What was reconstructed

A standalone game host used the public framework package pinned at
`edaec866e5faff038070dfc26be6a3d273893fee`. Its landscape developed through separate
style, terrain, contact, path, density, coast, motion and placement studies.
The retrospective read the host's contract, visible user decisions, stage reviews,
source/provenance records, runtime modules and saved technical reports. It did
not rerun the game's browser or hardware measurements. The host retains the full
33-source register, decision chronology and artifact links under
`docs/workflow-retrospective/`; private session data and art remain there.

## Causal decisions

| Trigger | Result | Reusable consequence |
| --- | --- | --- |
| First concept was too dark/fantastical | A brighter rounded original reference was selected | Approve visual direction separately from runnable geometry and production acceptance |
| The user asked how the island would be built | Compare per-cell texture, continuous regions and organic masks on one scene | Test a specific uncertainty with shared scene/camera and stated invariants |
| Objects looked detached | Compare contact shading, object-specific ground context and in-context separated layers | Inspect ground and dressed views; measure feet, not just alpha boxes |
| Reviewer chose subtle contact; user preferred ground context | Actual selection superseded the review recommendation | Preserve both statements and their order; never mistake reviewer preference for user choice |
| Soft terrain weakened route clarity | Keep clear route geometry, soften the pond selectively | Different surfaces can use different contour rules |
| Small sample concealed repetition | Expand to the whole connected island | Calibrate locally, then inspect repeated motifs, density and shared boundaries at full scope |
| Every path read as the same material | Introduce regional paving/earth/gravel with exterior edges | Variation should follow area function, preserving useful routes and junctions |
| Zoom exposed coarse exports | Re-export retained detail from original sources without changing the logical grid | Calibrate density, projection, zoom and effective DPR early; do not automatically regenerate art |
| Hard water slab and repeated grass remained | Compare coast/grass systems and select a mixed shore | Use shared masks and an intentional outer boundary; evaluate terrain without props |
| User limited work to landscape | Environmental motion and landmarks only | Liveliness does not authorize residents, pets, audio or extra gameplay |
| Placement and scale did not explain blocked cells | Calibrated physical bases drove blocking, reserves, approaches and contact export | Share transformations and distinguish collision from planting and interaction space |
| A reachable entrance was visually hidden | Move the obstructing house | Geometry success cannot substitute for actual clean arrival views |
| A later performance experiment was stopped | Camera experiment reverted; earlier verified work retained | Record the active candidate and cancellation; do not reuse canceled results as passing evidence |

The letters A/B/C were reused by different studies. In this case, the final
terrain refinement and the final coast treatment had different labels. Carry
study IDs and selected state forward, not bare letters or the last old table.

## Failure cases worth retaining

- Generic isometric assumptions introduced a half-cell offset and a supposed
  front-door test behind the building. Use public projection and real arrival poses.
- A before/after contact comparison also changed ground quantization. It was a
  combined change, not evidence that shadows alone caused the visual improvement.
- A malformed contact-export return shape blackened grass. Validate finite pixel
  values and all affected export profiles before accepting a renderer screenshot.
- A fitter treated build reservations as movement blockers. Keep those roles
  separate even when both derive from the same physical base.
- Extra full grass diamonds under irregular rock art created exposed corners.
  Painted relief is not necessarily a walkable raised surface.
- Instance-specific type names lost semantic family identity and disabled lights.
  Preserve family metadata; verify night and scene reload, not just frame counters.
- Mobile header overflow shifted the layout and touch targets. Test actual
  pointer type, viewport width and arrival before attributing failures to geometry.

## Evidence boundaries

The saved 2026-10-01 host summary reported 84 objects, 318 exclusive blocked cells,
760 reachable cells and 12 fronts. It recorded six tours/127 arrivals and separate
build, placement, bridge, keyboard, native motion/pause, scene reload and emulated
touch passes. Its source manifest contained 53 hash entries, all rechecked against
local files during this retrospective. The older 329-blocked/744-reachable snapshot
was superseded. None of these counts is a framework target.

User visual acceptance, physical-phone performance and 60 rendered FPS remained
open. Four-FPS source clips, runtime update counts and RAF intervals were different
measurements. The later canceled camera experiment was not an active improvement.

## Integration boundary

The consumer recipe now connects these lessons to existing v4 preflight, layout,
assembly, static, motion and final checks. It adds no acceptance schema, provider,
runtime behavior, art files or fixed size/performance default. The current packaged
placement checker compares calibrated rectangular extents; arbitrary polygon,
scaled-instance and access checks still require honest host-specific evidence.

The following stay project-local: island dimensions, masks, positions, chosen coast
style, clip frequency, density tiers, polygon tolerance and runtime scheduling.
Required art/layout checks and the generated-art/character I2V policy remain intact.
