# Generated ground slice experiment

User requested a test after rejecting the mixed generated-object/procedural-ground
appearance. This is a focused experiment on the existing village, not a newly
accepted whole game. Use the original user forest image for style and the actual
current ground plate for exact placement; existing cottage/tree sprites supply
object context. Built-in ImageGen remains the selected provider.

Generate a coherent grass/path/bank/water plate, then export measured256px crops
from its shared image origin. Neighbour crops must reconstruct the source exactly;
they are placed patches, not a generic reusable autotile set. Keep the current
world.ts geometry authoritative. Check visual/material agreement and geometry
correspondence separately. Do not hide model layout drift by silently changing
navigation or replacing poorly aligned generated ground with procedural paint.

Expose an explicit generated/original comparison in the existing host. Test the
bank, junction and bridge approach with ground-only and dressed views. Inspect
actual water motion if a generated water crop is used. Preserve previous assets,
prompts and evidence; record failed alignment or quality honestly.

The trial changes ground surface artwork. Existing bridge structures and character
art are not claimed to have become generated. Focused visual, seam/registration,
and affected traversal/motion checks replace full new-world production gates.
