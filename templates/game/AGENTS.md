# Working on this game

`PROJECT_CONTRACT.md` is the single source of truth for human requirements. Update it only after the owner agrees to a changed requirement.

This is a neutral technical calibration, not a finished game and not an art direction. Keep maps, rules, UI, assets, and generated artwork in this host. Do not copy artwork, palettes, names, or layouts from framework examples.

Before adding a world or commissioning/generating art, read the installed framework guides in `node_modules/isometric-framework/docs/CREATE_GAME.md` and select the relevant workflows in `node_modules/isometric-framework/skills/`. For a substantial world, begin with `isometric-visual-loop/SKILL.md` and complete its acceptance evidence. Use the public `isometric-framework` package exports; do not import package internals.

Choose world assembly (modular, composed ground, layered scene or hybrid), then generate new visible world and character assets through text-to-image or image-to-image. Reuse accepted generated art with its provenance. Character animation must use an approved generated facing image, image-to-video, reviewed frame extraction and packing. Preserve usable video alpha; otherwise inspect one color-key candidate. Halos, holes, lost subject colors, flickering edges or uncertainty require an approved cutout before packing: the video background remover on the reviewed clip, or the image background remover on the selected unkeyed frames. Direct generated sheets and authored movement frames are not production routes. Scenery and object animation may use image-to-video or another suitable technique on generated material. UI, collision, masks and blockout diagnostics are exempt; placeholders cannot pass finished-world acceptance.

Read the visual loop's references/asset-policy.md and use acceptance-plan version 4. Missing generation access or budget is a blocker. Resolve missing concept direction and rough layout under the approved contract before freezing acceptance; record the selected reference and provenance in host production data. Use production next for the next allowed stage and missing inputs. Implement eligible work before opening its evidence ticket, then capture the unchanged candidate. Complete preflight, layout plus blockout image review, a connected area, the whole static scene, motion and final review. Follow the visual loop for dependency scopes and actual runtime provenance binding.

Run `npm run build` for host type/build verification. Run the visual loop's separate `verify-world.py accept` command with production receipts for production acceptance; compilation never replaces it. Play the affected journey in a browser before describing an interactive change as verified.
